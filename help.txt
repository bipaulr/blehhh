PLEASE DO 'history -c' after and then 'clear'

CYCLE I - C PROGRAMS
1. lex.c  / lexinput.txt  / lex.txt  - lexical analyzer
2. ec.c   / ecinput.txt   / ec.txt   - epsilon closure of all NFA states
3. enfa.c / enfainput.txt / enfa.txt - remove epsilon transitions from an NFA
4. nfa.c  / nfainput.txt  / nfa.txt  - NFA to DFA subset construction
5. dfa.c  / dfainput.txt  / dfa.txt  - DFA minimization by table filling

CYCLE II - LEX AND YACC
6. name.l         / nameinput.txt / name.txt - reject lines containing name
7. var.l, var.y   / varinput.txt  / var.txt  - variable-name validation
8. calc.l, calc.y / calcinput.txt / calc.txt - calculator
9. ast.l, ast.y   / astinput.txt  / ast.txt  - BNF grammar and syntax tree
10. for.l, for.y  / forinput.txt  / for.txt  - FOR-statement syntax check

  Lexical analyzer:
    gedit lex.c lexinput.txt lex.txt &
    gcc lex.c -o lex
    ./lex

  Epsilon closure:
    gedit ec.c ecinput.txt ec.txt &
    gcc ec.c -o ec
    ./ec

  Remove epsilon transitions:
    gedit enfa.c enfainput.txt enfa.txt &
    gcc enfa.c -o enfa
    ./enfa

  NFA to DFA:
    gedit nfa.c nfainput.txt nfa.txt &
    gcc nfa.c -o nfa
    ./nfa

  DFA minimization:
    gedit dfa.c dfainput.txt dfa.txt &
    gcc dfa.c -o dfa
    ./dfa

  
    gedit name.l nameinput.txt name.txt &
    flex name.l
    gcc lex.yy.c -o name
    ./name

METHOD 3: YACC + LEX -> BISON + FLEX -> GCC -> RUN
Applies to these pairs:
  var.y  + var.l  - variable-name validator
  calc.y + calc.l - calculator
  ast.y  + ast.l  - abstract syntax tree
  for.y  + for.l  - FOR-statement validator

The .y file contains grammar rules; the .l file contains token patterns.
Bison's -y -d options generate y.tab.c and y.tab.h, which these lexers expect.
Flex generates lex.yy.c. Compile y.tab.c and lex.yy.c together.
Build one pair at a time: generated files are overwritten by the next build.

  Variable-name validator:
    gedit var.l var.y varinput.txt var.txt &
    bison -y -d var.y
    flex var.l
    gcc y.tab.c lex.yy.c -o var
    ./var

  Calculator:
    gedit calc.l calc.y calcinput.txt calc.txt &
    bison -y -d calc.y
    flex calc.l
    gcc y.tab.c lex.yy.c -o calc
    ./calc

  Abstract syntax tree:
    gedit ast.l ast.y astinput.txt ast.txt &
    bison -y -d ast.y
    flex ast.l
    gcc y.tab.c lex.yy.c -o ast
    ./ast

  FOR-statement validator:
    gedit for.l for.y forinput.txt for.txt &
    bison -y -d for.y
    flex for.l
    gcc y.tab.c lex.yy.c -o for
    ./for

If yacc is available, yacc -d calc.y can replace bison -y -d calc.y
(substitute var, ast or for as needed). Compile only after each command succeeds.

========================================
       TYPING INPUT IN THE TERMINAL
========================================
Press Enter after each input line. Programs may wait silently without a prompt.
Keep the final newline, especially for the Lex/Yacc examples.

ec, enfa, nfa, dfa:
  Read the counts and data described in their reference input files.
  They print the result and exit after all required values are entered.
  Example after ./ec:
    4 4
    0 e 1
    1 e 2
    2 a 3
    3 e 0

lex:
  Type C-like text. It prints tokens as it reads them.
  Press Ctrl+D on an empty line when finished to signal end of input.

name:
  Type one string per line. Each non-empty line prints ACCEPT or REJECT.
  Matching the substring name ignores letter case; empty lines are ignored.
  Press Ctrl+D on an empty line when finished.

var:
  Type ONE variable name and press Enter, for example abc1.
  It prints Valid variable or Invalid variable, then exits.
  Run ./var again for another case. Only letters/digits are allowed,
  and the first character must be a letter; underscores are invalid here.

calc:
  Type one expression per line, for example 2+3*4 or (2+3)*4.
  It prints the result and accepts the next expression.
  Press Ctrl+D on an empty line when finished.

ast:
  Type one expression per line, for example a+b*c or (a+b)*5.
  It prints a sideways syntax tree and accepts the next expression.
  Press Ctrl+D on an empty line when finished.

for:
  Type ONE complete FOR statement on one line and press Enter.
  Example: for(i=0;i<10;i++);
  It prints Valid FOR statement or Invalid FOR statement, then exits.
  Run ./for again for another case. This checks the PDF's restricted grammar.

gedit is optional; it only opens the files. The trailing & lets you keep using
the terminal while the editor is open. run.ps1 is a Windows helper and is not
needed for these Ubuntu commands.
