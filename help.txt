PLEASE DO 'history -c' after and then 'clear'

CYCLE I - C PROGRAMS
1. lex.c  / lexinput.txt  / lex.txt  - lexical analyzer
   lexsource.txt - actual source text read by the lexical analyzer
2. ec.c   / ecinput.txt   / ec.txt   - epsilon closure of all NFA states
3. enfa.c / enfainput.txt / enfa.txt - remove epsilon transitions from an NFA
4. nfa.c  / nfainput.txt  / nfa.txt  - NFA to DFA subset construction
5. dfa.c  / dfainput.txt  / dfa.txt  - DFA minimization by table filling

CYCLE II - LEX AND YACC
6. name.l         / nameinput.txt / name.txt - reject lines containing name
7. var.l, var.y   / varinput.txt  / var.txt  - variable-name validation
8. calc.l, calc.y / calcinput.txt / calc.txt - calculator
9. ast.l, ast.y   / astinput.txt  / ast.txt  - BNF grammar and syntax tree
10. for.l, for.y  / forinput.txt  / for.txt  - FOR-statement syntax check
11. vc.l / vcinput.txt / vc.txt / vcps.txt - vowels and consonants
12. while.l, while.y / whileinput.txt / while.txt / whileps.txt - WHILE syntax check
13. arith.l, arith.y / arithinput.txt / arith.txt - arithmetic-expression syntax check

  Arithmetic-expression validator:
    gedit arith.l arith.y arithinput.txt arith.txt &
    yacc -d arith.y
    flex arith.l
    gcc y.tab.c lex.yy.c -o arith
    ./arith
    Type one expression, for example a+b*c or (2+3)*4, and press Enter.
    Run ./arith again for another case. Identifiers, numbers, + - * /,
    unary signs and parentheses are supported. This checks syntax, not values.
    Division by zero is syntactically valid here; assignment and comparisons
    are unsupported. arithinput.txt is a reference, not redirected input.

METHOD 1: C SOURCE -> GCC -> RUN

  Lexical analyzer:
    gedit lex.c lexsource.txt lexinput.txt lex.txt &
    gcc lex.c -o lex
    ./lex lexsource.txt
    Or run ./lex and type lexsource.txt at the filename prompt.
    Edit lexsource.txt to change the source program being analyzed.

  Lexical analyzer from terminal input:
    gedit lexw.c &
    gcc lexw.c -o lexw
    ./lexw
    Type C-like source text; finish with Ctrl+D on an empty line.

  Epsilon closure:
    gedit ec.c ecinput.txt ec.txt &
    gcc ec.c -o ec
    ./ec

  Remove epsilon transitions:
    gedit enfa.c enfainput.txt enfa.txt &
    gcc enfa.c -o enfa
    ./enfa

  NFA to DFA:
    gedit nfa.c nfainput.txt nfa.txt &
    gcc nfa.c -o nfa
    ./nfa

  DFA minimization:
    gedit dfa.c dfainput.txt dfa.txt &
    gcc dfa.c -o dfa
    ./dfa

METHOD 2: LEX SOURCE -> FLEX -> GCC -> RUN
Applies to name.l and vc.l. These programs do not need yacc.

  Strings without the substring name:
    gedit name.l nameinput.txt name.txt &
    flex name.l
    gcc lex.yy.c -o name
    ./name

  Vowels and consonants:
    gedit vc.l vcinput.txt vc.txt &
    flex vc.l
    gcc lex.yy.c -o vc
    ./vc

METHOD 3: YACC + LEX -> YACC + FLEX -> GCC -> RUN
Applies to these pairs:
  var.y  + var.l  - variable-name validator
  calc.y + calc.l - calculator
  ast.y  + ast.l  - abstract syntax tree
  for.y  + for.l  - FOR-statement validator
  while.y + while.l - WHILE-statement validator
  prac.y + prac.l - practice variable-name validator

The .y file contains grammar rules; the .l file contains token patterns.
yacc -d generates y.tab.c and y.tab.h, which these lexers expect.
Flex generates lex.yy.c. Compile y.tab.c and lex.yy.c together.
Build one pair at a time: generated files are overwritten by the next build.

  Variable-name validator:  
    yacc -d var.y
    flex var.l
    gcc y.tab.c lex.yy.c -o var
    ./var

  Calculator:
    yacc -d calc.y
    flex calc.l
    gcc y.tab.c lex.yy.c -o calc
    ./calc

  Abstract syntax tree:
    yacc -d ast.y
    flex ast.l
    gcc y.tab.c lex.yy.c -o ast
    ./ast

  FOR-statement validator:
    yacc -d for.y
    flex for.l
    gcc y.tab.c lex.yy.c -o for
    ./for

  WHILE-statement validator:
    yacc -d while.y
    flex while.l
    gcc y.tab.c lex.yy.c -o while
    ./while

  Practice variable-name validator:
    yacc -d prac.y
    flex prac.l
    gcc y.tab.c lex.yy.c -o prac
    ./prac
